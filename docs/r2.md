# Cloudflare R2 setup

Contact CSVs are uploaded directly from the browser to a private R2 bucket. The application server only creates a short-lived presigned PUT URL; R2 credentials never reach the browser.

## Required environment variables

```text
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET=whatsapp-imports
```

Create an R2 API token scoped to the import bucket with object read/write permissions. Do not make the bucket public.

## CORS

Browser uploads use a presigned `PUT` with `Content-Type: text/csv`. Configure the bucket CORS policy for the app origin. For local development:

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

In production replace the local origin with the exact HTTPS application origin. Presigned URLs use the R2 S3 API hostname, not a custom domain.

## Retention

The importer does not immediately delete the source file so failed jobs can resume/retry. Configure an R2 lifecycle rule to delete `*/contact-imports/*` objects after a short audit/debugging window (for example 7–30 days) that matches the product's privacy policy.

## CSV format

A phone column is required. Supported names are:

```text
phone
phone_number
mobile
mobile_number
whatsapp
whatsapp_number
```

Optional name columns include `name`, `full_name`, `customer_name`, and `display_name`.

Local-format phone numbers use the two-letter default country chosen during import; international `+` numbers are accepted directly. Every imported row inherits the explicit marketing opt-in source and confirmation timestamp recorded when the user starts the import.
